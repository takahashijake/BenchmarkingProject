# v0.15 verification-gated reporting

## Architecture decision (recorded before implementation)

Baseline: fetched `origin/main` at `5220b8a1bf0c9be937348fafd0ecf81b1ee2c479`,
with a clean working tree. Reviewed merged PRs #5 (providers), #7 (durable
search/AutoML), #8 (parallel search), the historical catalog correction #6,
README, changelog, architecture, provider contracts, validation reports, storage,
verifier/descriptors, analysis, CLI, regression tests, CI and wheel smoke.

Persisted workflow configurations use schema 1. Robustness explicitly records
artifact schema 1; historical other workflows may omit that field. Manifests use
schema 1; catalog SQLite uses user_version 1. Fixed and nested-search recovery
workspaces have their own versioned schemas and are not reportable experiments.
The five stores write JSON/CSV, then seal. Their existing readers return mutable
mappings and some load predictions unnecessarily for presentation. The verifier
already validates all member JSON/CSV, topology, redundancy, metric aggregates,
identity, nested evidence and optional prediction/statistics recomputation. It
returns the normalized descriptor used by the catalog. No new serialization,
scientific identity, scoring, ranking or recovery format is needed.

Implement `reporting` downstream of `artifacts.verify.verify()`:

1. Loader: require a successful ordinary/deep verification, then adapt descriptor
   and selected JSON summaries. Do not load original datasets, execute providers,
   fit estimators, run studies or deserialize executable objects. Explicit opt-in
   admits only historical unsealed artifacts already accepted by the verifier;
   it never excuses a missing modern seal or another verification failure.
2. Model: frozen dataclasses, tuples and canonical JSON snapshots for polymorphic
   configuration/provenance. Preserve absent historical fields as unavailable.
   Carry metrics/directions, candidates/status, folds/repetitions, trial counts,
   selection, robustness and diagnostics separately. No mutable dict escapes.
3. Presentation: deterministic semantic HTML with inline CSS, no JavaScript,
   remote assets or generated timestamp. Escape every evidence string, including
   JSON, paths and identifiers; replace malformed Unicode for UTF-8 output.
   Show stored outer scores in nested leaderboards. Inner and final selection
   scores are explicitly selection-only. Reuse robustness interpretation code.
4. Publication: validate both inputs and destination, reject symlink paths and
   artifact/workspace ancestors, stage/fsync beside the destination, then publish
   atomically without clobbering by default. Explicit overwrite uses replacement.
   Clean temporary output on all exceptions. Never stage inside evidence.
5. Comparison: call existing pure `catalog.compare_descriptors()` directly;
   require no catalog. Add conservative presentation restrictions where its
   historical compatibility contract omits preprocessing/missing methodology.
   Display numerical deltas only for fully compatible evidence; partial status,
   reasons, failures, candidate changes and parameters remain visible.

Keep existing dependency boundaries and package/evaluator version 0.8.0. No
scientific kernel, schemas or fingerprints change. SHA-256 seals detect byte
changes relative to an inventory; they are not signatures of authenticity.
Hostile concurrent filesystem replacement is outside the existing artifact trust
boundary. Reports contain recorded configuration/provenance and should be shared
with that disclosure in mind.

## Usage and Python API

Reporting reads existing artifacts. These commands never execute an experiment:

```bash
benchforge report /path/to/experiment --output /tmp/report.html --deep
benchforge report /path/to/A --compare /path/to/B --output /tmp/comparison.html --deep
python -m webbrowser /tmp/report.html
# Linux desktop alternative:
xdg-open /tmp/report.html
# macOS: open /tmp/report.html; Windows: start "" C:\path\report.html
```

Open the generated file directly in a browser; no server or network is required.
Choose an existing output parent directory outside artifacts and recovery
workspaces. Existing output is rejected; use `--overwrite` deliberately.
Symlinks in input/output paths or evidence are rejected, including dangling
output links and symlink ancestors. Filesystems without hard-link support reject
new-file publication with an actionable error rather than weakening no-clobber
atomicity. Explicit overwrite uses atomic replacement where the filesystem
supports it. Interrupted staging is cleaned on catchable exceptions; uncatchable
process death can leave a harmless temporary file beside the destination, never
inside source evidence. File bytes are fsynced before publication; power-loss
persistence of directory entries depends on the filesystem.

```python
from pathlib import Path
from benchforge.reporting import (
    generate_report, load_report, load_comparison, render_report, render_comparison,
    ReportingError, VerificationError,
)

# Verification + immutable normalization, independent of rendering/publication.
model = load_report(Path("/path/to/experiment"), deep=True)
print(model.workflow, model.primary_metric, model.verification)
for candidate in model.candidates:
    print(candidate.identifier, candidate.status, candidate.scores)
html = render_report(model)  # pure; no filesystem reads

# The usual entry point validates destination and publishes atomically.
output = generate_report("/path/to/experiment", "/tmp/report.html", deep=True)
comparison = load_comparison("/path/to/A", "/path/to/B", deep=True)
comparison_html = render_comparison(comparison)
generate_report("/path/to/A", "/tmp/comparison.html", compare="/path/to/B", deep=True)
```

Frozen report dataclasses contain scalar values, tuples and canonical JSON
`Evidence` snapshots. `snapshot.decode()` returns a fresh private copy.
Source fields identify the persisted file or verified descriptor supplying each
polymorphic section. The report model is a public presentation API, not a new
persisted experiment schema. Renderers accept a loaded model; applications that
construct their own models are responsible for their scientific provenance.

`VerificationError` preserves existing verifier diagnostic codes in its message.
`ReportingError` also covers unsafe paths and failed publication. CLI failures
exit 2 and leave existing output unchanged. A scientifically failed/partial but
validly persisted experiment can still be reported successfully; missing/corrupt
or incomplete artifact publication cannot.

## Verification and historical evidence

The ordinary verifier always runs first. Standard verification checks hashes,
JSON/CSV, topology and redundant semantic evidence. `--deep` additionally
recomputes built-in scores from predictions and robustness bootstrap summaries
using existing scientific primitives. Standard verification does not recompute
all stored robustness effect summaries. Reports state which mode was used.
Reporting never executes external metric implementations, even in deep mode;
provider declarations and the explicit `external_metric_not_recomputed` warning
are retained. Installed providers and original dataset files need not exist.

Only historical unsealed artifacts accepted by the existing verifier can use:

```bash
benchforge report /path/to/pre-v0.8-artifact --allow-legacy --deep --output /tmp/legacy.html
```

Python uses `allow_legacy=True`. Missing modern manifests still fail, with or
without this option. Legacy reports prominently state that modern byte-integrity
guarantees are unavailable. Unknown schemas and verification failures cannot be
waived. Historical absent dataset summaries, schemas, timestamps or primary
metrics remain unavailable. A single run has no inferred primary metric/rank.
No artifacts, scientific identities, seals or recovery files are upgraded.

All artifact metadata is untrusted presentation text. HTML escapes paths,
identifiers, parameter keys/values, provider strings and diagnostic messages.
Evidence cannot supply URLs, HTML IDs, CSS or executable markup. The renderer
replaces malformed Unicode/control characters and bidi overrides in display,
while the model retains original JSON evidence. The HTML has a restrictive
content-security policy, embedded CSS, no JavaScript, fonts, images, CDN or
external runtime dependencies. It includes configuration and provider provenance;
review those recorded fields before sharing the report.

## Scientific presentation and comparison

Leaderboard means, standard deviations, ranks, statuses and budgets come from
stored evidence. Fixed/search variability is across folds; robustness variability
is sample standard deviation across completed repetition-level fold means.
Stored leaderboard ranks are preserved even when tied scores have different
presentation positions. Robustness repetition ranks retain competition ties.
Counts make single-observation/partial evidence explicit. No prediction rows or
full successful trial histories are embedded. Failed-family evidence may contain
its recorded trial diagnostics. Missing completed-fold evidence for failed search
families remains unavailable, rather than implying that no useful work occurred.

Search/AutoML leaderboard scores use outer evaluations only. Per-fold inner scores
and final full-data CV selection are shown separately with parameters, trial
counts and explicit selection-only labels. No inner score ranks a family. Choosing
a family from outer results still adds selection uncertainty. Robustness preserves
all stored paired deltas, repetition IDs, intervals, seeds, settings, rank
frequencies and the existing `analysis.robustness.interpret_pairwise()` language.
It adds no new significance test or statistical calculation.

Directory comparison reuses `catalog.compare_descriptors()` without SQLite.
Different workflow, task, dataset identity, primary metric or direction is
incompatible. Methodology/seed, incomplete evidence, family/mode or candidate-pool
differences are partial under existing catalog policy. Reporting additionally
marks preprocessing differences, missing fold/dependency evidence, differing
recorded dependency provenance and unsealed integrity as partial. Candidate
parameter changes alone do not invalidate a matched evaluation. Compatible
comparisons show natural score differences B minus A and direction-oriented
differences (positive means B better). All partial/incompatible comparisons
withhold numerical deltas; scores remain labeled observations of A and B.
Reasons, additions/removals, parameter changes, failures and both complete
experiment reports remain visible. Reports cannot establish population superiority,
statistical significance or causation. Repeated CV reuses rows; intervals describe
conditional resampling sensitivity, not independent population uncertainty.

## Reproducible examples

From the repository root after installation:

```bash
python examples/reporting/demo.py --output-dir /tmp/benchforge-reporting-demo
python -m webbrowser /tmp/benchforge-reporting-demo/reports/binary-benchmark.html
python -m webbrowser /tmp/benchforge-reporting-demo/reports/multiclass-search.html
python -m webbrowser /tmp/benchforge-reporting-demo/reports/regression-automl.html
python -m webbrowser /tmp/benchforge-reporting-demo/reports/robustness.html
python -m webbrowser /tmp/benchforge-reporting-demo/reports/robustness-comparison.html
python -m webbrowser /tmp/benchforge-reporting-demo/reports/compatible-comparison.html
```

Use a fresh output directory. The example first creates small binary fixed
benchmarks, multiclass nested search, regression AutoML and repeated matched CV
with existing public workflow APIs. It then reports persisted artifacts. It
compares compatible regularization variants and copied robustness evidence.
Finally it deliberately damages expendable copies and demonstrates actionable
corrupt/incomplete rejection without producing misleading reports. Original
experiments are preserved. The small trial/repetition budgets are demonstrations,
not recommended scientific sample sizes.

For existing results, reporting alone is sufficient:

```bash
benchforge report /path/to/binary-benchmark --deep --output /tmp/binary.html
benchforge report /path/to/multiclass-search --deep --output /tmp/multiclass.html
benchforge report /path/to/regression-automl --deep --output /tmp/regression.html
benchforge report /path/to/robustness-A --compare /path/to/robustness-B --deep --output /tmp/robustness.html
benchforge report /path/to/benchmark-A --compare /path/to/benchmark-B --deep --output /tmp/comparison.html
# Rejects damaged evidence, exits 2, and creates no output:
benchforge report /tmp/benchforge-reporting-demo/corrupt-copy --deep --output /tmp/rejected.html
```

## Implemented scope and deferred work

Implemented: all five workflows, all three tasks, secondary/custom metric
directions, failure/partial evidence, fold/repetition summaries, search/final
selection, exact robustness evidence, standalone accessible responsive HTML,
legacy opt-in, directory comparison, safe publication and installed-wheel use.
Reports have no generation timestamp and are byte-identical for identical input
evidence, locations and verification options. Recorded timestamps, runtimes and
source locations remain evidence and may differ between reproduced experiments.

Deferred: interactive JavaScript plots, PDF generation, custom themes, hosted
services, multi-experiment dashboards, prediction-level exploration, full trial
history browsing, signed authenticity, hostile concurrent filesystem mutation,
resource quotas for arbitrarily large adversarial artifacts and new statistical
inference. See [actual validation outcomes](v0.15-validation.md).
