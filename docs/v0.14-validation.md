## Process, leakage and recovery evidence

New `tests/test_search_parallel.py` and importable process fixtures cover:

- All three tasks, fixed/tuned/multiple family pools, optional final selection,
  AutoML plans and sealed artifacts/catalog ingestion.
- Frozen index plans and checkpoint task identities; actual worker-side inner
  partition and preprocessing training/statistics assertions. A worker mutates
  its private dataset after evaluation; neither siblings nor coordinator change.
- Forced outer-fold completion inversion, at most two active launches, unique
  scientific task dispatch, numerical thread environment caps and direct serial
  default compatibility.
- Real worker SIGKILL during an Optuna study and outer refit after a sibling
  checkpoint commits; unrelated tasks still succeed and resume computes only
  missing evidence. Failed families remain unranked.
- Socket/pipe handshakes at pre-rename, post-publication and artifact-sealing
  boundaries for search and AutoML. Independent coordinator processes contend
  for the same lock. SIGINT cleans active workers, preserves committed tasks,
  releases the lock and permits recovery with a different worker count.
- Real coordinator SIGKILL preserves the completed checkpoint. Because such a
  process cannot run cleanup, the test explicitly terminates its worker groups;
  the implementation makes no unsupported cleanup guarantee for this case.
- Corrupted checkpoint recomputation, full recovery without worker launches or
  estimator fits, crash classification, partial-family recovery, trial failures,
  outer-refit trial evidence and explicit all-failed errors.
- Malformed worker IPC, invalid scientific worker evidence, unexpected worker
  exceptions and publication failures abort orchestration. They are never
  converted into apparently scientific model failures.
- Actual portable subprocess/crash/recovery tests and a simulated non-POSIX
  cleanup branch. A dedicated Windows CI job runs the portable subset on Windows.

All waits are bounded and process-boundary synchronization uses handshakes,
rather than assumed fitting durations. Existing leakage sentinels, checkpoint
adversaries, providers, fixed-benchmark budgets/descendants, historical artifacts,
catalog and robustness regressions remain in the complete suite.

## Review and limits

Review checked shared scientific kernels, canonical aggregation/failure ordering,
bounded queues and private IPC files, atomic coordinator publication, exception
classification, generator closure and lock lifetime, native/model threading,
provider serial compatibility and unchanged scientific/artifact/workspace
identities. No distributed scheduler, persistent trial state, second evaluation
kernel or additional dependency was introduced.

Parallel execution rejects providers, custom registries and configured outer or
final wall-clock study timeouts. Final selection remains serial. There is no
memory-byte cap, universal speedup, cross-dependency bitwise numerical promise or
cleanup guarantee following uncatchable coordinator termination. Windows supports
direct-worker cleanup only; POSIX group guarantees require descendants to remain
in the group. See [architecture and full limits](v0.14-parallel-search.md).

PR/CI outcomes and final merge status must be checked on the published head;
neither a successful local suite nor the baseline CI substitutes for that gate.
