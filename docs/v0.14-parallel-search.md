# v0.14: resource-governed parallel nested search

## Architecture decision (recorded before implementation)

The inspected baseline is `ffa91482f70956903e9e1767008a927d8e878d40`.
The v0.13 complete family/outer-fold checkpoint is also the execution unit:
inner study, inner-only selection, outer-training refit, untouched validation
predictions and metrics. Fixed candidates use the same unit without a study.
AutoML continues to delegate to search. The existing evaluation kernel remains
the only owner of preprocessing, fitting and scoring.

| Alternative | Tradeoff | Decision |
| --- | --- | --- |
| Parallelize Optuna trials | Changes seeded TPE proposal history and complicates study recovery | Reject |
| ProcessPoolExecutor | A worker crash can break unrelated work; pending queue and termination need additional machinery | Reject |
| New multiprocessing scheduler | Requires duplicate lifecycle, IPC and cleanup logic | Reject |
| Reuse explicit subprocess supervisor | Existing bounded dispatch, private disk IPC, public process cleanup and crash isolation; interpreter startup per task | Select |

Extract the current outer-fold body into one shared scientific function. Preserve
the direct serial path by default. A frozen plan records canonical candidate and
fold identities and immutable index tuples; each fresh interpreter receives a
private resolved dataset and exact assignments. Only available worker slots are
serialized/launched. Results are validated by the existing recovery evidence
validator, then published by the coordinator. Reassemble family results in
configuration/fold order, never completion order. Worker count stays outside all
scientific identities and workspace compatibility inputs.

Extend the supervisor narrowly for unbudgeted non-POSIX subprocess execution.
POSIX keeps session/process-group cleanup. Windows can terminate/reap the direct
worker, without a descendant-termination claim. No hard search budget is added.
Do not use executable serialization in workspaces or published artifacts; the
existing trusted private temporary IPC is the only pickle boundary.

## Failure policy

Run every planned missing task, including remaining folds of a family whose
other fold failed. This avoids completion-order-dependent scheduling and retains
all completed evidence for recovery. A family is ranked only when every required
fold succeeds. Its representative failure is the first failed fold in canonical
order; failure trial evidence includes completed studies and failed studies in
fold order. Worker crashes have a distinct `WorkerCrash` classification.
Unexpected worker exceptions, invalid IPC/evidence and publication/coordinator
errors abort the attempt instead of becoming scientific model failures.
All-families-failed remains an explicit error. Cancellation closes the scheduler
before releasing the workspace lock; no ordinary artifact is sealed on interrupt.

## Compatibility and resource boundary

Default `workers=1` keeps direct serial execution and pinned-provider support.
Parallel execution requires built-in model/search/data registries and no selected
providers. Resolve data once in the coordinator. Reject outer or final Optuna
wall-clock timeouts with parallelism, even without recovery: competing studies
cannot preserve the historical timeout/proposal semantics. Trial-count studies
remain individually serial. Reject explicit model `n_jobs` other than one;
limit numerical-library threads in workers. Worker count must be an integer in
`[1, logical CPU count]`, excluding booleans.

Each active task requires a private dataset copy, interpreter, estimator and
complete result plus temporary disk space. This bounds active tasks and IPC
files, not memory bytes or total retained scientific evidence. Startup and
validation overhead may outweigh concurrency benefits on small datasets.
No speedup or memory-limit guarantee is made. Numerical equivalence is tested
within the same dependency environment; floating point/native-library changes
can affect results across environments.

Deferred: trial continuation, hard task budgets, running-trial journals,
distributed scheduling, memory enforcement, parallel provider reconstruction,
Windows Job Objects and cleanup following uncatchable coordinator termination.

## Parallel/recovery lifecycle

1. Validate worker count, registry/provider policy, study timeouts and `n_jobs`.
2. Resolve the dataset, dependency identities, spaces and exact outer/inner folds
   in the coordinator. AutoML first resolves its existing deterministic plan.
3. Acquire the established workspace lock, if requested, and validate experiment
   compatibility. Build canonical immutable task assignments. Worker count is
   absent from workspace schema 1 and its unchanged execution contract.
4. Load and validate every completed outer task. Only missing/rejected tasks
   enter the pending metadata list; no completed task is dispatched again.
5. Launch at most `workers` fresh Python interpreters through
   `python -m benchforge.execution.worker`. This is spawn-safe: no inherited
   registry mutations or fork state, and no multiprocessing bootstrap requirement
   for API callers. Pickle only the active requests into a private coordinator
   `TemporaryDirectory`. Discard worker stdout/stderr instead of buffering them.
6. After worker exit and cleanup, read its complete private IPC file. Validate
   scientific evidence through the same v0.13 validator used at publication and
   reuse. Publish successes atomically in the coordinator. Invalid IPC or evidence
   aborts; a nonzero process exit is a distinct worker crash.
7. Reconstruct all families in configured candidate and outer-fold order. A family
   missing any successful fold is unranked. Rank complete families through the
   existing leaderboard function. Run/reuse final selection serially in the
   coordinator only after the leaderboard is fixed; it cannot alter outer scores.
8. Seal ordinary artifacts. AutoML holds the same lock through parent sealing.
   Resume reseals a fresh output from valid tasks if publication was interrupted.

Runtime-only `SearchResult.execution_mode`, `execution_workers`,
`execution_planned_tasks` and `execution_diagnostics` report serial/subprocess mode
and canonical task outcomes (`reused`, `success`, `failed`). The CLI prints task
counts, rejected checkpoints and remaining work. Parallel family durations sum
newly executed task wall times (including startup/failures); total duration is
coordinator wall time, so overlapping family times are not additive elapsed time.
These fields are deliberately
not persisted: no new artifact member/schema or manifest exception is needed.
Existing checkpoint diagnostic fields retain their v0.13 meanings. All-failed
attempts raise explicitly and do not publish a misleading successful result.

## Process/platform limits

POSIX uses the existing `start_new_session=True` launch and SIGKILL group cleanup,
including descendants that remain in the group, with bounded direct-worker waits.
Windows uses new interpreters and direct `Popen.kill()`/`wait()` cleanup. It has
no process-group or descendant-termination guarantee and rejects hard budgets.
The Windows CI job exercises actual spawn-safe scientific equivalence, crash
isolation, recovery and direct cleanup. Linux's Python 3.12/3.13 matrix exercises
the full suite, including real signal and publication-boundary tests.

Ctrl+C/SIGINT closes active workers before releasing cooperative locks and does
not seal ordinary artifacts. Uncatchable coordinator death, default SIGTERM,
power loss, a second interruption during cleanup, deliberately escaped process
groups and uninterruptible kernel I/O cannot promise worker cleanup. Successfully
committed checkpoints survive; an incomplete study/refit restarts from its original
seed. Uncatchable coordinator death can also leave private temporary IPC files;
they are never used as recovery inputs. See the v0.11 supervisor and v0.13 local
filesystem/threat boundaries, which remain applicable.

The worker cap limits active processes, not resident bytes. Numerical-library
thread environment limits are applied before scientific imports, and
`threadpoolctl` also limits active native pools in each fitting worker. Estimator
`n_jobs` overrides that request additional jobs are rejected before dispatch.
There is no persistent worker pool: task isolation costs imports and dataset
serialization for every fold, but avoids cross-task mutable estimator/RNG state.
Final selection remains serial; large final studies do not gain concurrency.

## Runnable commands

Choose a worker count no greater than the machine's logical CPU count.

```bash
benchforge search configs/examples/breast_cancer_search.yaml --workers 4 \
  --workspace artifacts/recovery/parallel-binary
# Ctrl+C after a completed tasks/*.json appears, then:
benchforge search configs/examples/breast_cancer_search.yaml --workers 2 \
  --resume artifacts/recovery/parallel-binary
benchforge search configs/examples/iris_multiclass_search.yaml --workers 2
benchforge search configs/examples/diabetes_regression_search.yaml --workers 2
benchforge automl configs/examples/breast_cancer_automl.yaml --workers 4 \
  --workspace artifacts/recovery/parallel-automl
benchforge automl configs/examples/breast_cancer_automl.yaml --workers 2 \
  --resume artifacts/recovery/parallel-automl
benchforge automl configs/examples/diabetes_regression_automl.yaml --workers 2
benchforge automl configs/examples/iris_multiclass_automl.yaml --workers 2 --plan-only
```

Plan-only validates the worker option but never dispatches fitting or creates a
workspace. Verify/catalog the printed sealed artifact directory, not a workspace.
Existing Python calls compose `workers=N` with `checkpoint_dir=Path(...)` and
`resume=True`; both new keywords are optional and defaults retain serial behavior.
