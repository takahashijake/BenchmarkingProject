## Architecture and implemented behavior

- Frozen typed artifact descriptors, candidate/evaluation models and diagnostic reports sit above
  the five existing workflow formats. Workflow result classes remain separate.
- Signature-based recursive discovery is deterministic, reports malformed/ambiguous evidence,
  rejects symlink members and treats nested benchmark runs/AutoML searches as parent-owned evidence.
- A common schema-1 manifest writer validates first, protects every regular file recursively except
  its own manifest, and writes the seal last. Child seals are protected by their parent inventory.
- Verification checks byte inventories/hashes independently of semantic decoding, schema versions,
  timestamp/CSV/JSON structure, candidate/failure coverage, metric/ranking semantics, trial budgets
  and selection evidence, split separation and prediction membership. Deep verification reconstructs
  fold metrics and robustness paired/bootstrap/ranking summaries without source data or retraining.
- Legacy artifacts remain usable with explicit integrity/metadata limitations. New registry identity
  inputs are persisted so semantic fingerprints can be checked offline without substituting current
  registries for historical evidence.
- Standard-library SQLite schema 1 separates experiments from locations. Candidate/metric summaries
  are location-scoped; prediction/trial histories stay in files. Whole-batch transactions, foreign
  keys, uniqueness constraints, semantic collision checks and ingestion byte snapshots preserve
  idempotency and immutable history. Fresh verification records are retained.
- CLI commands expose standalone verification and catalog ingest/list/show/verify/compare, filters,
  stable portable IDs with unambiguous prefix lookup, and JSON output.
- Historical comparison uses explicit workflow/task/dataset/metric/methodology/fold compatibility,
  reports candidate/parameter/ranking/failure differences, keeps minimized scores natural, and
  refuses corrupted evidence. Different replica observations are surfaced, never silently combined.
- Documentation and Python 3.12/3.13 GitHub Actions CI accompany the 0.8.0 release version.

## Correctness issues addressed

Persisted runs previously used an unresolved configuration fingerprint. It depended on CSV source
paths and omitted resolved dataset content, so relocation could change identity and changed content
could reuse identity. Runs now use a recorded content-resolved fingerprint method; the unresolved
`RunConfig.fingerprint` API stays compatible. Regression tests change source bytes and relocate
identical CSV content.

Benchmark/search/AutoML fingerprints previously included metric presentation order. New fingerprints
canonicalize that order. Verification retains the original legacy benchmark algorithm and reads
historical artifacts without changing their stored identity.

The pre-existing unanchored `artifacts/` ignore pattern hid `src/benchforge/artifacts/` from Git and
Ruff traversal. It now applies only to root output artifacts. Tests explicitly cover missing and
symlink-replaced indexed locations, conflicting legacy identities, re-sealed replacement bytes,
empty failed-candidate prediction headers and malformed timestamps/JSON so these boundaries retain
useful failure diagnostics. CLI filesystem failures now use the existing error/exit-code convention.

No estimator fitting, preprocessing, split generation, search proposal or leakage boundary was
refactored. Existing training semantics and leakage regression tests remain intact.

## Intentional limitations

Manifests establish byte integrity relative to an unsigned seal, not authenticated authorship.
Historical artifacts cannot recover fingerprint inputs or metadata that were never stored. Different
fingerprint algorithms are not retrospectively merged. Catalog locations are immutable, and moving
files does not erase old unavailable locations; location removal/rebinding is deferred. Comparison
uses deterministic first-location selection and flags different replica observations rather than
choosing a scientific winner. Runs without a declared primary metric have limited comparison support.
No significance testing, population inference, retraining, remote registry or web UI is introduced.
Filesystem changes after an ingestion snapshot are detected by subsequent verification rather than
locked across SQLite and the filesystem. A failed writer can retain unsealed evidence for diagnosis;
only successfully completed evidence receives a valid manifest.
