# v0.13: durable nested search and AutoML

## Decision and scientific boundary

Recovery is opt-in, serial, and coordinator-owned. A logical task is one candidate
family on one outer fold: its entire inner study, selection, outer refit,
predictions, and metrics. Fixed baselines use the same boundary without a study.
Only validated successes are published. A killed trial or outer refit restarts
that whole task. Previously completed folds survive a later family failure;
failed families retain the existing unranked failure semantics and are retried.
If every family fails, the existing `FamilySearchError` is raised.

Approach A (complete outer-fold checkpoints) was selected. Approach B (individual
trial recovery) was rejected: historical Optuna trials do not restore a seeded
TPE sampler's random state. Replaying history, failures, startup sampling, and
version-dependent sampler behavior needs a separate execution contract. Continuing
a reconstructed study must not be advertised as exact continuation. Approach C
(Optuna RDB/journal storage) persists study history but does not solve sampler
state, outer refit publication, or BenchForge evidence validation. It would also
introduce another mutable source of truth. No Optuna database, pickled sampler,
model serialization, parallel search, or scheduler is introduced.

The optional final full-data search is a separate task, keyed by the winning
family. It cannot change the outer-CV leaderboard. Its plan includes exact folds
and derived seeds. A final checkpoint preserves the existing `FinalCandidate`,
including complete trial evidence and selection score. A fixed final candidate
has the existing scalar CV selection evidence, without invented trial records.

AutoML reconstructs its deterministic plan and generated `SearchConfig` before
opening the same search workspace. Its policy fingerprint, resolved selection,
allocation, unused remainder, and complete canonical plan bind the child search.
There is no AutoML evaluator. The lock spans both child and parent sealing.

## Commands and API

Start with a new directory. After Ctrl+C, use the identical configuration with
`--resume`; abrupt process termination is supported too.

```bash
benchforge search configs/examples/breast_cancer_search.yaml \
  --workspace artifacts/recovery/binary
benchforge search configs/examples/breast_cancer_search.yaml \
  --resume artifacts/recovery/binary

benchforge search configs/examples/iris_multiclass_search.yaml \
  --workspace artifacts/recovery/multiclass
benchforge search configs/examples/iris_multiclass_search.yaml \
  --resume artifacts/recovery/multiclass

benchforge search configs/examples/diabetes_regression_search.yaml \
  --workspace artifacts/recovery/regression
benchforge search configs/examples/diabetes_regression_search.yaml \
  --resume artifacts/recovery/regression

benchforge automl configs/examples/breast_cancer_automl.yaml \
  --workspace artifacts/recovery/automl
# Press Ctrl+C after at least one tasks/*.json file has appeared.
benchforge automl configs/examples/breast_cancer_automl.yaml \
  --resume artifacts/recovery/automl
```

In that AutoML example, each valid completed outer-fold task avoids its inner
trial fits and outer refit on resume. The interrupted task starts over. CLI
summaries report reused tasks, newly executed tasks, rejected checkpoints, and
remaining work. These counts describe avoided computation; validation and
planning still cost time and no wall-clock speedup is promised.

```python
from pathlib import Path
from benchforge import load_search_config, load_automl_config, run_search, run_automl

search = load_search_config("configs/examples/iris_multiclass_search.yaml")
result = run_search(search, checkpoint_dir=Path("artifacts/recovery/python-search"))
resumed = run_search(search, checkpoint_dir=Path("artifacts/recovery/python-search"), resume=True)
print(resumed.checkpoint_reused, resumed.checkpoint_executed, resumed.checkpoint_invalid)

automl = load_automl_config("configs/examples/diabetes_regression_automl.yaml")
run_automl(automl, checkpoint_dir=Path("artifacts/recovery/python-automl"))
result = run_automl(automl, checkpoint_dir=Path("artifacts/recovery/python-automl"), resume=True)
print(result.search_result.checkpoint_reused)
```

`checkpoint_dir` follows the established fixed-benchmark Python API. `resume=True`
requires a directory. `--workspace` and `--resume` are mutually exclusive;
`automl --plan-only` cannot create or resume workspaces. Existing calls without
these options retain their execution and fingerprint behavior.

## Workspace lifecycle and validation

```text
recovery/demo.lock          # sibling OS-backed file lock; never delete while active
recovery/demo/
  workspace.json           # schema 1, execution contract, experiment digest, task map
  tasks/<task-sha256>.json  # versioned envelope, task/experiment IDs, payload digest
```

A fresh workspace never overwrites an existing path. Resume requires a matching
manifest; malformed or incompatible manifests fail before fitting or reuse.
An interrupted initial manifest publication may leave an unusable workspace
with no committed tasks; start a new workspace in that case.

Workspace compatibility includes the existing scientific fingerprint plus actual
resolved dataset values/order/index/dtypes, target metadata, exact outer and inner
folds, final fold plans, model capability identity, fixed parameters/mode/IDs,
preprocessing, metric semantics/direction, primary metric, seeds and their versioned
derivation contract, search-space definitions/versions/defaults, trial budgets,
final policy, Python and NumPy/pandas/SciPy/sklearn/Optuna versions, evaluator
version/contract, selected provider declarations and version pins, and AutoML plan.
Output/workspace paths, timestamps and runtimes do not enter identity. Historical
artifact fingerprints, catalog identities, and schemas remain unchanged.

Every task key includes the experiment digest. Payloads are safe JSON data, with
SHA-256 integrity checks. Reuse validates fold membership, exact prediction index
order/uniqueness, target truth, class/score validity, recomputed metrics through the
existing metric kernel, trial numbering/counts/states, fixed overrides, selected
parameters/objective, and sampler/estimator seeds. Aggregation and ranking use the
ordinary search kernels after mixing recovered and newly executed fold evidence.
Publication runs the same validation. Serialization/publication errors abort;
they are never converted into scientific model failures.

Missing tasks run normally. Truncated JSON, bad checksums, unsupported task
versions, or invalid evidence are reported as rejected checkpoints and recomputed.
Manifest schema, execution-contract, or experiment mismatch rejects the workspace.
Unknown members, symlinks (including temporary files, lock path and workspace
ancestors), and nonregular task members fail closed. Unpublished regular temporary
files are ignored. No task is accepted just because its filename exists.

A nonblocking OS-backed `filelock.FileLock` prevents cooperative concurrent
writers. Kernel lock ownership is released after process death; the sibling lock
file may remain and is reusable. JSON is flushed and fsynced to a same-directory
temporary file, atomically renamed, then the directory is fsynced where supported.
Only the coordinator publishes. Ordinary local filesystems with reliable locks,
rename, and fsync are assumed. Network filesystem guarantees require independent
validation. A malicious process modifying the directory concurrently is outside
this cooperative-workspace threat model. Digests detect corruption, not forgery:
they do not authenticate predictions or prove that fitting occurred.

## Reproducibility and limits

With deterministic built-ins and unchanged inputs/versions, resumed and
uninterrupted runs preserve fold assignments, proposals in completed studies,
selected parameters, predictions, metrics, fingerprints, rankings and final
selection. Timings, validation overhead and diagnostic fields can differ.
Incomplete studies restart from their original derived seeds.

Workspace execution rejects configured outer-study or final-study wall-clock
timeouts. Independent time-stopped runs can complete different numbers of trials;
no exact reproducibility claim is safe. Such configurations remain supported
without a workspace. Trial-count budgets are required for recovery.

Built-in registries and explicitly selected v0.12 version-pinned providers are
supported. Unversioned custom registries are rejected for recovery; their ordinary
serial API remains supported. Provider code is trusted and must honor its declared
version and stateless deterministic contract. Custom metrics are recomputed during
online checkpoint validation using the activated pinned implementation. Published
offline verification retains its explicit custom-metric limitation and never
imports providers. Dependency or provider changes require a new workspace.

Workspaces are recomputable caches, separate from published sealed artifacts.
Resume always assembles and seals ordinary new search/AutoML evidence; it does not
reuse a possibly partial artifact directory. A crash during sealing leaves an
unsealed output for diagnosis; resume writes a new artifact from valid checkpoints.
Use the printed artifact path with `benchforge verify` or the catalog, never the
workspace. Delete an unused workspace only after all writers have stopped.

Deferred: trial-level continuation, wall-clock budget recovery, parallel nested
search, distributed locking, model deployment, and cryptographic authenticity.
