# v0.16 binary calibration, thresholds and decision analysis

A probability estimate and a classification decision answer different questions.
This workflow evaluates both using deterministic nested stratified cross-validation.
It compares fixed built-in candidates, optionally calibrates their probabilities,
trains a decision threshold on inner held-out evidence, and evaluates that trained
procedure on untouched outer folds. Every candidate uses the same outer folds.

## Run a complete experiment

```bash
benchforge decision configs/examples/breast_cancer_decision.yaml
benchforge decision configs/examples/breast_cancer_decision_cost.yaml
# Substitute the printed experiment directory:
benchforge verify artifacts/decision/decision_... --deep
benchforge report artifacts/decision/decision_... --deep --output /tmp/decision.html
benchforge catalog ingest artifacts/decision/decision_... --database /tmp/decision.sqlite
# Runs both examples twice, verifies equality and creates four offline reports:
python examples/decision/demo.py --output-dir /tmp/benchforge-decision-demo
```

Reports require an existing destination parent outside evidence/workspaces, and
never fit models, load original data or activate providers. They use static HTML,
inline CSS, safe escaping and the existing atomic report-publication contract.
The experiment result records positive-class probabilities separately from the
historical `PredictionRecord.score`, which can contain margins in old workflows.

```python
from benchforge import load_decision_config, run_decision_analysis
from benchforge.artifacts import verify
from benchforge.reporting import generate_report

config = load_decision_config("configs/examples/breast_cancer_decision.yaml")
result = run_decision_analysis(config)  # persist=False evaluates without writing
print(result.fingerprint, result.status)
print("Positive label:", result.dataset.target_labels[1])
for candidate in result.candidates:
    print(candidate.identifier, candidate.status, candidate.rank)
    for fold in candidate.folds:
        print(fold.fold_id, fold.selection.threshold, fold.selected.confusion,
              fold.reference.confusion, fold.probability_quality)
assert verify(result.artifact_directory, deep=True).passed
# Choose an existing output parent directory:
generate_report(result.artifact_directory, "/tmp/decision.html", deep=True)
```

`DecisionConfig`, `CalibrationConfig`, `ThresholdConfig`, `DecisionResult` and
`DecisionAnalysisError` are also available from `benchforge.decision`. Results
are frozen typed models containing tuples/scalars and immutable canonical JSON
snapshots. `model_dump()` returns an independent serialization; runtime artifact
paths are excluded. An all-failed execution seals the failure evidence and raises
`DecisionAnalysisError` carrying `.result`; CLI exits 2. Partial failures retain
completed outer folds and aggregate observations but never receive a rank.

## Configuration contract 1

```yaml
schema_version: 1
task: binary_classification
dataset: {name: breast_cancer}
outer_split: {n_splits: 3}
inner_split: {n_splits: 3}
models:
  - {id: logistic, name: logistic_regression, parameters: {max_iter: 1000}}
  - {id: forest, name: random_forest_classifier, parameters: {n_estimators: 30}}
calibration: {method: sigmoid, n_splits: 3}
threshold:
  policy: optimize
  objective: f1
primary_metric: selected.f1
reliability_bins: 10
seed: 42
output: {directory: artifacts/decision}
```

Datasets use existing built-in or CSV/Parquet loading, preprocessing and target
encoding. Optional preprocessing settings retain their existing defaults.
Only binary classification, stratified shuffled folds, fixed built-in classifier
configurations, serial execution and `n_jobs=1` are supported. No multiclass,
regression, custom registries, providers, parallel workers, checkpoints, AutoML,
hyperparameter search, groups, time-series splits, sample weights or deployment
refit is implied. Evaluation assumes exchangeable rows; repeated entities and
temporal dependence require split methods outside this workflow. Unsupported fields/tasks/models fail explicitly; all split and
class-count constraints are preflighted before fitting. Estimator parameter
errors that require fitting become visible candidate failures. Unexpected software
exceptions propagate instead of producing synthetic successful observations.

Calibration methods: `none` (default), `sigmoid`, `isotonic`. None requires genuine
`predict_proba`; raw margins never become probabilities. The calibration kernel
can use a supported classifier's decision function, but no additional margin-only
estimator or arbitrary-provider interface is introduced. All five current built-in
binary estimators are supported through the ordinary model registry.

Isotonic requires at least **1000 training observations at every inner/final fit
boundary**, optionally raised with `isotonic_min_samples`. Those are pooled OOF
responses for a single calibrator (`ensemble=False`), not counts per calibration
fold. This intentionally excludes the small breast-cancer example. For all
methods, every applicable training/validation split must contain both classes,
and each class must have enough rows for its stratified fold count. The overall
class count alone is insufficient: additional inner/calibration nesting reduces
available training rows. A large total sample count does not establish adequacy
for a rare positive class. Sigmoid often has lower variance at small sample sizes;
method choice must be committed before inspecting outer outcomes.

Threshold policies: `fixed` applies `value` (default 0.5); `optimize` uses an
explicit grid (default 0.00, 0.05, …, 1.00). Grids contain 1–10001 unique finite
numbers in [0,1] and are sorted canonically. Predictions use **p >= threshold**,
including equality. Threshold 0 predicts all positive; threshold 1 still predicts
positive for p=1, so the bounded grid cannot guarantee an all-negative policy
when exact-one probabilities occur. Zero-positive predictions are valid whenever
a grid threshold exceeds all observed probabilities. Precision is zero when no
positive prediction exists. F1 uses the binary positive class 1.

Objectives are `f1`, `balanced_accuracy` (maximize), or
`misclassification_cost` (minimize). Costs are finite nonnegative numbers,
defaulting to 1 each, and may both be zero. Exact rational objective comparisons
use integer confusion counts and the decimal representations of configured costs.
Exact ties prefer decimal distance to 0.5, then the smaller threshold. Trial rows
store float display values plus confusion counts for exact reconstruction.
Fixed policy also retains an inner selection record, but never uses its objective
to change the configured threshold.

```text
cost per sample = (false_positive_cost * FP + false_negative_cost * FN) / N
```

Increasing false-negative cost can favor more positive decisions; increasing
false-positive cost can favor fewer. These costs are assumptions supplied by the
user, not empirically established utilities. See the asymmetric-cost example.
**In sklearn breast_cancer, 0=malignant and 1=benign.** Thus its FP means a
malignant case called benign, and its FN means a benign case called malignant.
The example assigns the FP a higher hypothetical cost. Always inspect the stored
ordered target labels, particularly for file data: the existing loader's mapping
is preserved, and its class 1 need not be the human condition called “positive.”
This demonstration is not a clinical policy.

Declare a leaderboard primary metric: `selected.f1` (default),
`selected.balanced_accuracy`, `selected.accuracy`, `selected.precision`,
`selected.recall`, `selected.misclassification_cost`, `probability.brier_score`,
`probability.log_loss`, `probability.roc_auc` or `probability.ece`. Threshold
objective and final ranking criterion are separate declarations. All use outer
evaluation only. Costs, Brier, log loss and ECE minimize; other choices maximize.

## Why three nested boundaries matter

For each candidate and shared outer fold:

1. Reserve outer validation. Build inner folds strictly within outer training.
2. For each inner fit, construct a fresh full preprocessing/model pipeline. With
   calibration, cross-fit that pipeline again strictly inside inner training,
   fit the calibrator using its pooled training-only OOF raw responses, and refit
   the base pipeline on the whole inner-training boundary. Obtain probabilities
   only for inner validation.
3. Pool those inner held-out probabilities in sample-index order. Select a
   threshold using only that evidence. The calibrator generating an inner
   validation probability has never seen that observation.
4. Fit the final outer pipeline using outer training only. With calibration,
   repeat training-only calibration CV and the full-boundary base refit.
5. Obtain outer-validation probabilities once, and apply the selected cutoff and
   the matched fixed-0.5 reference. Only these evaluations enter the leaderboard.

The full pipeline is inside sklearn `CalibratedClassifierCV`, with explicit
`ensemble=False` and `n_jobs=1`; preprocessing is never fitted before calibration
CV. Sklearn prefers `decision_function` for calibration when available, otherwise
`predict_proba`. There is no prefit estimator. Fold indices are persisted in global
dataset position space; calibration indices are mapped to relative positions only
when calling sklearn. All fold and estimator seeds use the existing SHA-256
seed helper with distinct declared roles. No global RNG seeding is introduced.
See the [sklearn calibration guide](https://scikit-learn.org/stable/modules/calibration.html)
and [CalibratedClassifierCV API](https://scikit-learn.org/stable/modules/generated/sklearn.calibration.CalibratedClassifierCV.html).

For M candidates, O outer folds, I inner folds and K calibration folds, expect
**M × O × (I+1) × (K+1)** base-pipeline fits with calibration, versus
**M × O × (I+1)** without it. There are M × O × (I+1) calibrator fits. The main
example uses 96 base fits and 24 calibrator fits. Fixed thresholds still record
inner evidence under this contract. No speedup or hard-resource-budget guarantee
is claimed; numerical-library threads are capped during serial evaluation. Reproduction
assumes the same numerical environment; cross-platform/BLAS bitwise equality is
not guaranteed, especially for probabilities near threshold boundaries.

## Reading the evidence

Discrimination measures ordering: ROC-AUC can be high even when probabilities
are numerically poorly calibrated. Calibration describes correspondence between
predicted probabilities and outcome frequencies. Lower Brier score or log loss
measures better probabilistic prediction overall; each also reflects discrimination
and does not isolate calibration. Probability quality does not change when the
same probabilities are classified at a different threshold.

Brier score is mean((p-y)^2). Binary log loss uses float64 sklearn epsilon clipping
at exact 0 and 1. ROC-AUC is recorded where defined; the accepted stratified
workflow rejects single-class evaluation folds. Reliability bins use uniform
`linspace(0,1,B+1)` edges, left-closed/right-open, with the final bin including 1.
All bins are retained; empty-bin means are null. ECE is
sum(count/N * abs(mean_probability-positive_fraction)). It is a **descriptive**
diagnostic sensitive to bin edges, number of bins and sample size; it is not a
confidence bound or proof of calibration, especially for small/imbalanced folds.
None of these scores proves reliability after deployment distribution shift.

Each outer fold stores its own threshold. Different training rows can produce
different thresholds; their variability matters when judging stability. Averaging
them does not yield a validated deployment cutoff. An optimized inner objective
can perform worse than 0.5 on outer validation; honest evaluation must retain that
outcome. The matched reference controls for probability estimation because both
policies use the exact same held-out probabilities. Precision, recall, confusion
counts and costs describe different tradeoffs; no single threshold dominates all
utilities and prevalences.

Aggregates are unweighted outer-fold means and population standard deviations
(ddof=0), using the established aggregation kernel with max-absolute rescaling to
avoid overflow for large finite costs. Confusion counts are per fold; they are not
averaged probabilities. Only complete candidates share competition ranks (1,1,3)
on their declared outer primary metric. Partial/failed candidates have no rank;
partial aggregate observations remain labeled incomplete. Fold variability is not
a confidence interval, overlapping CV folds are not independent datasets, and
leaderboard differences make no statistical-significance claim. Choosing a model
from the leaderboard introduces additional model-selection uncertainty.

## Artifact contract, verification and compatibility

A new workflow type `decision`, configuration schema 1 and artifact schema 1:

- `decision_config.json`: complete resolved declarations (no providers).
- `decision_result.json`: immutable scientific result, dataset content digest and
  original label mapping/truth, complete outer/inner/calibration plans, all seeds,
  inner probabilities and selection curves, outer probabilities and both decision
  policies, confusion matrices, probability bins, aggregates, failures and ranks.
- `metadata.json`: creation metadata, dependency versions and fingerprint.
- `manifest.json`: existing schema-1 SHA-256 seal over every protected member.

Machine-readable schemas are in `schemas/decision-config-v1.schema.json` and
`schemas/decision-result-v1.schema.json`; Python models provide
`model_json_schema()` as well. Artifact serialization excludes runtime paths.
Identity includes canonical policy, resolved feature/target content digest,
original dataset identity/label metadata, model classes/resolved defaults/registry
capabilities, dependency versions and explicit scientific/seed methodology.
A separate target digest binds the stored truth sequence into identity and can
be reconstructed offline without features. Output/source paths are excluded.
Normalized catalog dataset identity uses the
resolved **content SHA-256 and original ordered label meanings**, preventing comparison of changed values under the
same built-in dataset name. Result dataset metadata also retains that original
source identity for interpretation.

Publication stages on the same filesystem under `.decision-stage-*`, validates
all semantics, writes, flushes and fsyncs members and seals, then atomically renames to
a new timestamp/fingerprint/UUID directory. Discovery ignores staging directories.
A small `.decision-publication.lock` serializes cooperating final publishers and
permits Windows renaming to a nonexistent destination. It is not an experiment.
Caught failures clean staging; destination collisions never overwrite evidence.
Uncatchable process termination can leave unpublished staging; it is never recovery
state. Rename/power-loss durability depends on the filesystem. Hostile concurrent
filesystem replacement and signed provenance are outside the existing trust boundary.

Standard and deep verification both reconstruct **all** decision scientific records:
exact deterministic plans from stored truth, every subset/disjointness/seed and
class count, threshold curves/tie breaking from inner probabilities, predictions,
confusions, costs, metrics, probability diagnostics, aggregate observations and
complete-only ranks. Recomputed numeric diagnostics use the existing verifier's
roundoff tolerance (relative 1e-10, absolute 1e-12); selection thresholds, counts,
assignments and seeds remain exact. The stored target digest is independently recomputed. Original features/files, fitted estimators and
providers are unnecessary. Missing calibration evidence, unsupported schemas and
inconsistent/rehashed records fail. Hashes detect corruption, not authenticity or
whether recorded fitting plans were actually obeyed. Offline verification cannot
recreate original feature content from its digest or prove training provenance.

Catalog ingestion and reports reuse the established verification boundary. Their
compatibility includes decision/calibration/threshold/cost/binning/preprocessing,
versions and actual fold plans. Different resolved content is incompatible;
different decision methodology is conservatively partial and report deltas are
withheld. There is no artifact migration: old workflows, score contracts,
scientific identities, legacy readers/seals, SQLite schema and package/evaluator
version **0.8.0** retain their meanings. A new decision artifact always requires
its seal; legacy opt-in cannot manufacture a historical decision representation.
