## Feature validation

The initial dedicated reporting run passed 77 cases and failed two test setup
calls using `DatasetRegistry.load` instead of its existing `resolve` API. Those
new fixtures were corrected. The complete dedicated suite then passed **93 tests
in 9.78s**. Combined reporting and artifact/catalog regressions passed **174 tests
in 13.42s**. No original test was changed or weakened.

The tests generate all five workflows for binary classification, multiclass
classification and regression. They independently read source JSON and reconstruct
means from fold evidence, check variability and metric directions, nested selection
versus outer evaluation, exact paired statistics/ranks/interpretations, ties,
failed families, all-failed robustness and partial fold retention. Other checks
cover immutable snapshots, deterministic HTML bytes, source file hashes, forbidden
fit/study/dataset/provider execution, offline custom metrics, missing original
CSV files, legacy opt-in, malformed JSON/CSV/manifests, numeric overflow,
rehashed semantic corruption, symlinks and sealed/workspace destinations,
no-clobber races, explicit atomic overwrite, read-only paths, failed/interrupted
publication, text/Unicode injection, CLI subprocess execution and no database.

Six reproducible HTML examples were generated by `examples/reporting/demo.py`;
the corrupt/incomplete disposable copies were rejected with verifier diagnostic
codes and no output. Static HTML parsing checks semantic table structure, unique
IDs/internal links, absence of executable tags/attributes, external resources
and CSS network references. A manual Chromium launch initially could not run
because the environment lacked `libnspr4.so`; this is an environment limitation,
not evidence of browser rendering success.
