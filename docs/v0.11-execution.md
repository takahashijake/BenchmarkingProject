# v0.11 fixed-benchmark execution supervision

This feature applies to `benchmark`. Nested search, AutoML, robustness and single
`run` evaluation keep their existing execution contracts. Package version remains
0.8.0, matching main; v0.11 describes this feature milestone, not a published release.

## Architecture decision

Use a small, in-memory scheduler over explicitly managed subprocesses. Each
candidate gets a new interpreter and a POSIX session/process group, established
by `Popen(start_new_session=True)` before Python starts. The coordinator owns
scheduling, deadlines, result collection, checkpoints and artifact publication.
The worker calls the existing candidate wrapper and `run_benchmark` kernel with
the coordinator's resolved dataset and immutable folds. No new evaluator exists.

Alternatives considered:

| Approach | Termination and isolation | Serialization / testing | Decision |
| --- | --- | --- | --- |
| Extend ProcessPoolExecutor | Future timeouts do not stop training; public per-worker termination unavailable on 3.12/3.13; one crash breaks pool | Convenient pickle transport, difficult cleanup without private APIs | Keep only for legacy unbudgeted non-POSIX parallel mode |
| Dedicated multiprocessing supervisor | Individual processes can be killed, but sessions need child setup handshakes; fork is risky with native threads | Spawn is portable; pipes need bounded readers or disk transport | Rejected: more setup/race handling than subprocess sessions |
| Explicit subprocess/IPC | Group established at launch; exit status and bounded wait are public APIs on both supported Python versions | Private temporary files avoid partial IPC reads and pipe-buffer deadlocks | Selected |
| Small reusable scheduler over isolated workers | Caps active work and isolates crashes; no persistent queue | Typed internal function/tasks/results boundary, real-process fixtures | Selected minimal scheduling layer, not a general orchestration engine |

Only available slots are launched; no executor queue holds all candidates. A
finished worker is reaped and its process group killed before its capacity is
reused. Crash failures do not poison other candidates. Final results remain in
configuration order; successful leaderboard ties retain identifier ordering.

IPC pickles contain the resolved task and complete result, in a private temporary
directory created by the coordinator. They are never loaded from a workspace,
user-supplied result path, or historical artifact. These are trusted local worker
messages, not a security boundary against a malicious estimator. Complete files
are read only after a zero exit status. Broken IPC/startup/coordinator errors
propagate rather than becoming scientific estimator failures. Worker stdout and
stderr go to the null device; no unbounded capture or dataset output log is kept.
Estimator exceptions retain the existing structured failure message.

## Public interfaces and budgets

```bash
benchforge benchmark configs/examples/breast_cancer_suite.yaml --workers 2 \
  --candidate-timeout 120 --run-timeout 600 --workspace artifacts/recovery/bounded
```

```python
from benchforge.execution import ExecutionOptions, run_benchmark_suite
result = run_benchmark_suite(config, workers=2,
    execution_options=ExecutionOptions(candidate_timeout=120, run_timeout=600))
```

Both limits are optional, finite positive seconds; zero, negative, boolean and
non-finite values are rejected. The default worker count is one. Unbudgeted
single-worker execution preserves the prior direct/custom-registry path.
Budgeted execution always uses a subprocess, including one worker, and requires
the default model registry. Logical-CPU worker caps remain enforced. Supervised
workers constrain BLAS/OpenMP threads; budgeted/parallel candidates reject
explicit estimator `n_jobs` other than one. No memory limits are enforced or
memory capacity inferred. Each active candidate needs dataset/result copies and
temporary disk space. Startup and serialization overhead may dominate short fits;
there is no measured speedup claim.

Candidate time starts before IPC preparation and includes interpreter startup,
imports, fitting, evaluation and result serialization. The run deadline uses a
monotonic clock from API entry, including preparation and resume validation.
Once reached it stops new launches and kills active groups. Polling is every
10 ms when active, plus coordinator operations and cleanup. Limits govern
candidate execution, not a hard bound on dataset loading, synchronous local
filesystem operations, checkpoint validation/commits or final artifact writing.
Those coordinator operations are not preempted. Late results observed after a
deadline are conservatively rejected, even if the worker may have just finished.
Run deadline takes precedence when both limits expire together.

## Outcomes and interruption

Existing `failures.json` fields remain unchanged. `error_type` distinguishes:

- Estimator exceptions: existing exception type (usually `FoldExecutionError`).
- `CandidateTimeout`: started worker exceeded its candidate budget.
- `RunTimeout`: started worker stopped by the run deadline.
- `WorkerCrash`: nonzero process exit; message records observed exit code.
- `NotStarted`: candidate was never launched because the run budget expired.

Failures have no rank or metric. CLI calls comparisons with failures incomplete;
ranks compare completed candidates only and imply nothing about unavailable work.
Zero successful candidates are supported. Budget exhaustion returns a partial,
verifiable artifact containing explicit failures; CLI exit status remains zero
when it successfully produces this report. Invalid policy/errors return two.

Ctrl+C/SIGINT raises `KeyboardInterrupt` in the coordinator. It closes the scheduler,
kills outstanding groups, waits for workers, releases the workspace lock and
publishes no final artifact. CLI returns 130. No daemon threads or custom
coordinator signal handlers are used. Workers ignore SIGINT because cleanup is
coordinator-owned. A second interrupt during cleanup, SIGKILL of the coordinator,
kernel failure or power loss cannot be guaranteed to clean workers up.

Termination uses SIGKILL immediately, with a two-second wait per worker. An
unconfirmed exit raises an explicit cleanup error; capacity is not reused.
POSIX process-group guarantees cover descendants that retain the group. A
process deliberately escaping through `setsid`/`setpgid` is outside this contract.
Killed descendant zombies may require the system init process to reap them;
they cannot continue training. Uninterruptible kernel I/O cannot be forcibly
bounded by a Python application. Linux is exercised by CI. Other POSIX systems
use the same APIs but need platform-specific validation. Non-POSIX systems
reject budgets rather than using ineffective timeouts; legacy unbudgeted modes
remain available there.

## Diagnostics and recovery compatibility

Supervised runs expose `BenchmarkResult.execution_diagnostics` and
`execution_options`. A new optional `execution.json` has independent
`schema_version: 1`, `policy` (candidate/run timeout or null), and `candidates`
(identifier, outcome, elapsed_seconds, reason). It is sealed with published
artifacts but excluded from scientific fingerprints. Workspace diagnostics use
the same schema and atomic writer; on interruption running work is `Cancelled`
and on unexpected coordinator failure it is `CoordinatorError`. Reused work is
`reused`, ordinary failures `EstimatorFailure`, and successes `success`.
Diagnostics describe the latest attempt and are not reusable candidate evidence.
They are written at the end/interrupt, not a crash-durable running journal.

Checkpoint schema 1 and execution semantic contract remain unchanged: the fitting
kernel has not changed. Budgets are execution policy, excluded from workspace
identity and benchmark fingerprints. A new attempt may choose different budgets
and worker count. Verified historical successes are reused without fitting even
when the new candidate limit is shorter than their historical duration. The new
run deadline still applies to all remaining work; reuse does not launch an
unbudgeted estimator. Failed, crashed, cancelled and timed-out candidates have
no successful checkpoints and are attempted again from the beginning on resume.
Dataset, split, seed, model, metric and dependency compatibility checks, atomic
writes, lock ownership and symlink protections retain v0.10 contracts.

## Runnable demonstration

Run `python examples/bounded_benchmark.py` from the repository after installing
BenchForge. It performs a normal bounded benchmark, creates a budget-exhausted
checkpoint workspace, resumes with generous limits, verifies the sealed result
and checks catalog ingestion. It uses a temporary directory and prints artifact
locations. For a real interrupted workspace, rerun the same CLI configuration
with `--resume <workspace>` and suitable limits, then `benchforge verify <Artifacts
path printed by the CLI>`. Never verify/catalog the checkpoint workspace itself.

Future work may add tested Windows Job Objects, memory enforcement and stronger
OS containment. These are not implemented guarantees. Folding nested search into
this supervisor requires its own leakage and recovery design.
