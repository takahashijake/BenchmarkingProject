## Optional analyzer review

Rubber Duck continues to flag existing pickle IPC, subprocess calls and
adversarial process tests. These statuses were not modified or suppressed.
Review found no untrusted artifact/checkpoint input reaching pickle loads.
IPC files are created by the coordinator in its private TemporaryDirectory,
with internally generated names, trusted local tasks and zero-exit result reads.
The worker is a private Python execution entry point; invoking Python on an
arbitrary pickle is not a service offered to untrusted artifact data. Subprocess
argv contains the current interpreter, a fixed module and internal paths, with
no shell interpretation. `os._exit`, fixed test subprocesses and group signals
intentionally exercise crashes and cleanup. No new provider executable objects
are sent through this transport. Activated providers with worker budgets or
parallelism are rejected before import.

This review classifies these specific reports as non-blocking within the
existing trusted-local-execution threat model. Same-user compromise, malicious
estimators, escaped process groups and hostile Python code remain outside that
contract. The optional analyzer's failure status must not be reported as passing.

## Scientific and compatibility review

The scientific fold kernel remains the only fitting/scoring implementation.
Provider activation changes registry resolution and metric lookup; it does not
introduce new folds, preprocessing, aggregation, optimization or ranking code.
Dataset validation occurs before model fitting. Estimators are cloned for each
construction and class/regressor tags are checked. Factories receive centralized
seeds and independent parameter dictionaries. Metric callbacks receive private
array copies and must return finite real scalars.

A deterministic fixture was captured from the isolated v0.11 implementation.
Binary, multiclass and regression regressions compare exact scientific
fingerprints, full fold-plan digests, seed inputs and ranking, with tolerance-aware
prediction and aggregate checks. Existing nested leakage, failure, budget,
concurrency, locking, interruption, crash and process-cleanup tests remain intact.

Provider declarations use immutable tuples and frozen records. Registry mappings
are instance-local. Search definitions returned to callers are independent
copies. Activated provider declaration order and task order are canonical;
discovery order and unrelated installed packages do not enter identity.
Distribution version remains provenance, separate from declared scientific
implementation and metric versions. Metadata cannot establish an honest version
bump or hardware-independent bit equivalence.

## Adversarial findings corrected

- **Worker startup:** reproduced baseline short-budget failures; removed eager
  scientific imports instead of relaxing timeouts or disabling tests.
- **Loader error attribution:** a KeyError raised inside a dataset loader no
  longer masquerades as an unknown dataset name.
- **Mutable estimators:** clone factories' outputs so a singleton factory cannot
  reuse fitted estimator state between folds.
- **Fixed-parameter mutation:** pass private fixed-parameter copies into search
  proposers and retain overwrite rejection.
- **Dataset semantic drift:** supplement declared plugin dataset identity with
  resolved data/schema/target-label content identity.
- **Checkpoint missing metadata:** require candidate provider declarations to
  agree with the workspace experiment even when a corrupted payload has a newly
  computed checksum. Recompute corrupt candidates; retain legacy builtin reuse.
- **Boolean API spoofing:** reject `True` as interface version 1 explicitly.
- **Offline trust:** test verification/catalog ingestion in a fresh interpreter
  with an import finder that refuses the provider module. Persisted entry-point
  strings remain inert data.
- **Numeric callbacks:** accept NumPy real scalars while rejecting booleans,
  arrays, complex results, NaN and infinity.

## Evidence and packaging

The independent example is installed as a separate distribution with an entry
point; tests exercise discovery, inspection, all five public CLI workflows,
AutoML planning, Python APIs, search budgets/fixed parameters and recovery.
Artifact verification and catalog ingestion check the resulting evidence.
CI installs this distribution before testing on both Python 3.12 and 3.13, builds
the wheel, reinstalls it and executes `scripts/wheel_smoke.py` from an external
working directory. The smoke asserts that BenchForge imports from installed
site-packages and exercises benchmark, search, checkpoint reuse, deep verification
and catalog ingestion.

Final suite counts, CI links and merge result are recorded in the implementation
PR and final engineering report. No claim of performance speedup or secure plugin
sandboxing is made. The package metadata intentionally retains the established
0.8.0 evaluator version; v0.12 is this implementation milestone. A release-version
change with deliberate fingerprint migration remains a separate release decision.
